# 생태계 하위 네 화면 가독성 개선

## 빈 날짜 피드백과 Changelog 표시 (2026-10-15 후속)

조회 달력은 최초 진입 시 빈 오늘 날짜 구획을 만들지 않고 실제 항목으로 이동한다. 사용자가 직접 선택한 날짜에 자료가 없을 때만 짧은 안내와 가까운 실제 날짜 버튼을 제공한다. 매크로·행사의 반반 배치와 날짜 연동을 유지한다.

개발 업데이트의 전체 보기는 GitHub Changelog처럼 월별 그룹과 날짜·유형·제목·제품 태그를 중심으로 정리한다. 상세 설명은 항목 클릭으로 확인하고 기존 기간·검색·정렬·환경 필터와 공식 링크를 유지한다. 콘텐츠 유형은 바로 보이는 선택 버튼, 제품 태그는 해당 제품 필터로 연결한다. 제품별 버전 이력은 간결한 선/점 타임라인을 유지한다. 이 절이 앞선 개별 대형 카드·전체 보기의 날짜별 그룹 표시를 대체한다.

## 반반 달력·릴리스 타임라인 최종 기획 (2026-10-15 승인)

이 절이 이전 고정 너비/개발 업데이트 달력 기획을 대체한다. 매크로 소식과 행사·이벤트의 조회 달력/목록은 데스크톱에서 1:1 너비와 같은 높이로 맞추고, 태블릿·모바일에서는 위아래로 쌓는다. 고정 최대 너비를 제거하고 날짜 칸에는 건수, 첫 제목 최대 두 줄, 추가 건수를 표시한다. 오늘/선택일/자료 있는 날을 구분하며 월 이동·날짜 선택·180ms 스크롤 동기화를 유지한다. 달력 숨김 상태에서는 목록이 전체 너비를 사용한다.

개발 업데이트는 달력과 보기 버튼을 제거한다. 전체 업데이트는 공개일별 목록, 제품별 버전 이력은 공개 순서를 선과 점으로 연결한 세로 타임라인이다. 정식은 채운 점, 프리릴리스는 빈 점과 옅은 제목으로 구분한다. 버전·유형·공개일·요약·적용 일정·공식/비교 링크 및 상세 패널을 유지하고 Git 분기 관계를 만들지 않는다.

검증: 개발 업데이트 달력 부재, 제품별 릴리스 순서/단계/상세 연결, 기간/검색/정렬 유지, 매크로/행사 두 열의 실제 너비·높이, 여러 날 행사 표시, 양방향 스크롤, 390px 반응형을 확인한다.

## 조회 달력 크기 통일 (2026-10-15 최종 보정)

이 절이 아래 개발 업데이트의 280px/점 표시형 및 화면별 달력 열 비율을 대체한다. 매크로 소식·행사 및 이벤트·개발 업데이트의 조회 달력은 공통 열 너비 448px, 헤더 72px, 6주 42칸으로 통일한다. 날짜 칸은 모바일 72px/데스크톱 80px이며 화면 너비 안에서 줄어든다. 데이터가 있는 날짜는 건수 배지와 첫 항목 제목, 전체 제목 툴팁으로 표시한다. 없는 날짜는 표시하지 않는다. 여러 날 행사, 날짜 선택, 월 이동 및 목록 스크롤 연동을 유지한다. 기간 선택 팝오버는 별도 입력 도구로 유지한다.

## 개발 업데이트 개편 실행 계획 (2026-10-15 승인)

이 절이 개발 업데이트에 관한 이전 표시 규칙보다 우선한다. 기존 작업 브랜치에서 진행한다.

1. 데이터 계약: 환경·제품·공식 릴리스 단계·원문 근거·네트워크별 일정을 선택 필드로 추가한다. 기존 항목과 호환한다. 공식 GitHub 메타데이터는 기존 수집 항목을 검증하는 용도로만 사용하고 목록을 대체하지 않는다. 원문에서 확인되지 않은 값은 미확인으로 남긴다. 업데이트 API는 페이지 처리를 지원해 100개 이후 이력도 검색한다.
2. 화면: 개발 업데이트 전용 컴포넌트를 만들고 전체 업데이트/제품별 버전 이력 탭, 제품·유형·공개일·추가 필터, 날짜 그룹 목록, 근거가 있는 주요 업데이트, 접근 가능한 상세 패널을 구현한다. 브랜드·기존 내비게이션을 재사용한다.
3. 달력: 기본 닫힘, 작은 왼쪽 달력과 오른쪽 목록을 동기화한다. 없는 날짜 구획을 만들지 않고 가까운 항목으로 이동한다. 공개일이 기준이다.
4. 검증: 검색·날짜 경계·불명확한 릴리스 단계·환경·중복 제거·100개 이후 페이지·상세 키보드·반응형·달력 연동을 확인한다. 로컬 수집 누락은 원문/수집 상태와 대조해 기록하며 DB를 임의 수정하지 않는다.

중요도 점수만으로 필수 업그레이드를 단정하지 않는다. 원문에 근거가 있는 변경만 강조하고 과거 공지는 긴급 공지처럼 취급하지 않는다. 공개일과 적용일을 분리하고 KST/UTC를 명시한다. 미확인과 해당 없음을 구분한다. 날짜 범위는 적용 후 반영하고 단일 필터 선택의 중복 칩을 만들지 않는다.

구현 전 점검: 로컬 17건 중 AvalancheGo 0건(원문도 0건), 저장된 수집 cursor는 v1.15.1을 가리킨다. 중복 원문 URL은 0건. 누락 원인은 cursor만으로 확정할 수 없다. Granite 적용시각은 서로 다른 글에서 00:00Z/16:00Z로 달라 원문 근거 일정만 노출해야 한다.

기준: 2026-10-15 · `feature/ecosystem-readability` · Aidenteti-Crew `deploy`의 `51c04b7`에서 시작.

## 범위와 목적

체인·프로젝트, 매크로 소식, 행사·이벤트, 개발 업데이트의 읽기와 탐색을 개선한다. 생태계 홈은 범위 밖이다. 기존 API·DB·수집 데이터는 유지하고 웹의 표시와 조작을 바꾼다.

| 화면 | 기본 보기 | 탐색 | 항목에서 먼저 보여줄 정보 |
|---|---|---|---|
| 체인·프로젝트 | 카드 | 이름·설명·개발사 검색, 다중 분야 선택, 이름/중요도 정렬 | 프로젝트명, 분야, 요약, 개발사, 공식 링크 |
| 매크로 소식 | 리스트 | 검색, 발행 기간, 출처, 종류, 최신/오래된순, 리스트/달력 | 발행일, 출처, 종류, 제목, 요약 |
| 행사·이벤트 | 달력 | 검색, 행사 기간, 상태, 참여 방식, 종류, 달력/리스트 | 일정·시간대, 상태, 제목, 주최자, 장소/온라인, 원문·신청 링크 |
| 개발 업데이트 | 리스트 | 검색, 발행 기간, 출처, 종류, 최신/오래된순, 리스트/달력 | 발행일, 출처, 실제 종류, 제목, 요약, 버전·적용일 |

## 데이터와 표시 규칙

- `contentEntrySchema`가 크롤러 응답의 `subKind`, `version`, `upgradeName`, `activatedAt`, `relatedProject`를 보존한다. `kind=UPDATE`는 화면에 반복 출력하지 않는다. `subKind`가 알려진 값일 때만 사람에게 읽히는 종류를 표시한다.
- 소식과 업데이트의 발행일·적용일, 달력 날짜는 한국시간 기준이다. 화면에 이 기준을 표시한다. 행사는 응답의 행사 시간대를 행에 함께 표시하며 달력의 날짜 배치는 한국시간 기준이다.
- 프로젝트 분야 이름은 API의 실제 `categories`에서 가져온다. `Analytics & Data`를 포함한 모든 분야를 검색하고 여러 개 선택할 수 있다. 그룹은 처음 6개를 보여주고 필요할 때 펼친다.
- 검색과 필터는 함께 적용한다. 결과 건수·빈 결과·초기화 동작을 제공한다. 리스트와 달력의 선택은 화면별로 브라우저에 기억한다.
- 달력은 월 이동과 날짜 선택을 제공한다. 날짜를 고르면 그날의 항목을 목록으로 읽을 수 있다. 여러 날의 행사는 시작일부터 종료일까지 해당 날짜에 나타난다.
- 현재 API 요청은 프로젝트 최대 500개, 매크로·업데이트 최대 100개, 행사는 상태별 최대 100개다. 화면의 검색·필터는 받은 항목에 적용된다. 수집량이 이 범위를 넘을 때는 API 페이지 이동이 후속 작업이다.

## 검증 기준

1. 실제 로컬 데이터 235개 프로젝트에서 `Analytics & Data` 15개만 골라 보고, 검색어를 더했을 때 결과가 함께 좁혀진다.
2. 매크로와 업데이트에서 발행일·출처를 원문을 열기 전에 확인할 수 있다. 개발 업데이트에는 반복 `(UPDATE)`가 없다.
3. 행사 달력과 리스트를 오가며 같은 자료를 확인한다. 상태 필터를 바꾸면 해당 자료가 있는 월로 이동한다.
4. 390px 모바일에서 필터와 달력에 가로 넘침이 없고, 날짜 칸은 건수로 읽힌다.
5. 관련 테스트와 수정 파일 린트가 통과하고, 타입 검사에서 이번 변경 파일의 신규 오류가 없다.

## 홈 스타일 반영 (2026-10-15 후속 요청)

- 홈의 다크 배경·둥근 카드·은은한 보라/금색 계열 색감을 하위 네 화면에 적용한다. 제목 옆 화면 아이콘과 건수를 배치한다.
- 검색과 필터를 하나의 라운드 탐색 바로 묶는다. 기본 select를 Radix 기반 맞춤 팝오버로 교체하고, 선택한 조건을 제거 가능한 칩으로 표시한다.
- 리스트/달력 전환은 아이콘만 표시하되 접근성 이름·툴팁·선택 상태를 제공한다.
- 기사와 행사는 넓은 카드로 표시한다. 프로젝트는 분야 선택 시 선택한 분야의 프로젝트를 하나의 그리드로 모은다.
- 데스크톱에서는 달력과 선택 날짜 목록을 나란히, 모바일에서는 위아래로 배치한다.

## 오늘 기본 선택·타임라인 후속 변경

이 절은 위의 날짜 자동 이동·기간 프리셋·별도 행사 아카이브 탐색을 대체한다.

- 달력 첫 진입은 이번 달·오늘(KST) 선택. 오늘 소식이 없으면 선택은 유지하고 최근 게시물을 별도 표시한다.
- 행사 달력 오른쪽은 선택 날짜 이후 같은 달의 날짜별 타임라인이다. 오늘 행사가 없으면 빈 안내와 다가오는 일정을 함께 표시한다. 해당 달에 일정이 없으면 다음 일정으로 이동 버튼을 제공한다.
- `예정 / 지난`을 같은 화면에서 전환한다. 지난 탭은 최근 지난 행사로 이동하며, 정렬은 예정 가까운순/먼순, 지난 최근순/오래된순을 제공한다. 별도 지난 이벤트 전체 보기 버튼과 행사 기간 프리셋은 제거한다.
- 출처·행사 종류·참여 방식 등 선택지가 하나인 필터는 숨긴다. 검색 결과가 아닌 화면 원본 데이터 기준으로 판단한다.
- 매크로·개발 업데이트는 달력으로 발행 시작일·종료일을 선택한다. 두 날짜 모두 포함한다. 매크로 COLLAB 표시를 `협업·도입`으로 변경한다.
- 개발 업데이트는 기술 글과 소프트웨어별 릴리스 발표 이력을 구분한다. 출시 후보는 버전 표기에서 구별하며, 버전 간 부모/분기 관계를 생성하지 않는다.
- 프로젝트 분야 선택은 바깥 클릭·Escape로 닫히는 팝오버로 변경한다. 선택값은 유지한다.

## 날짜 적용과 선택 표시 보정

- 날짜 팝오버의 선택 중 상태와 실제 적용 조건을 분리한다. 첫 클릭은 시작일, 두 번째 클릭은 종료일이며 적용 버튼을 누를 때만 결과를 바꾼다. 같은 날짜를 두 번 선택하면 하루 범위다.
- 종료일 선택 전에는 적용을 비활성화한다. 취소·바깥 클릭·Escape는 기존 적용 조건을 유지한다. 전체 기간도 임시 선택을 지운 뒤 적용한다.
- 단일 선택인 출처·종류·날짜와 검색어의 중복 칩을 제거한다. 조건은 해당 조작부에만 보이고 결과 영역에는 초기화 버튼만 제공한다. 프로젝트의 다중 분야 칩은 유지한다.

## 달력·타임라인 양방향 동기화

- 행사 달력 모드는 여러 달의 일정을 시간순으로 연결한 내부 스크롤 타임라인을 표시한다. 스크롤 상단의 날짜에 맞춰 달력의 월·선택 날짜를 갱신한다.
- 달력 월 이동·날짜 클릭은 타임라인의 해당 날짜 위치로 이동한다. 일정이 없는 날짜는 빈 일정 구획을 삽입하고, 여러 날 진행되는 행사는 선택한 날짜에도 표시한다.
- 달력 모드의 예정/지난은 각각 오늘·최근 지난 일정으로 이동한다. 리스트 모드에서는 기존 기간 구분·정렬을 유지한다.
- 사용자 달력 조작의 이동 요청과 스크롤로 관측한 날짜를 별개로 관리해 반복 스크롤을 방지한다. 데스크톱 달력은 sticky로 고정한다.
- 연속 스크롤 중에는 달력 표시를 유지하고 마지막 스크롤 후 180ms에 한 번 동기화한다. 달력 직접 조작은 대기 중 동기화를 취소하고 즉시 이동한다.
- 달력은 6주·42칸의 일정한 높이로 표시한다. 스크롤로 따라간 날짜는 배경색 없이 얇은 테두리로 표시하며 직접 선택한 날짜는 기존 강조를 사용한다.
- 행사 외부 링크 문구는 `자세히 보기`로 표시한다. 매크로·개발 업데이트에는 스크롤 동기화를 확대하지 않는다.

## 보기 전환 최종 보정

- 행사 예정/지난 탭을 제거하고 모든 일정을 날짜순 연속 타임라인으로 통합한다. 리스트/달력 양자 선택 대신 `달력 표시/숨기기` 아이콘 버튼 하나를 사용한다.
- 달력을 숨기면 동일 타임라인이 전체 너비로 펼쳐진다. 표시 여부를 바꿔도 보고 있던 날짜를 유지하고, 다시 표시한 달력도 해당 날짜를 가리킨다.
- 프로젝트는 카드/리스트 보기 아이콘을 제공한다. 검색어·선택 분야·정렬·펼친 그룹을 유지하며 보기 설정은 브라우저에 기억한다.

## 매크로·개발 업데이트 달력 동기화 확대

사용자 후속 요청으로 소식 화면의 달력 모드에도 양방향 동기화를 적용한다.

- 오른쪽은 날짜 제목과 기사 카드가 연속되는 목록이며 행사 타임라인의 선·점은 표시하지 않는다.
- 목록 스크롤이 멈춘 뒤 180ms에 왼쪽 달력 월·선택 날짜를 갱신하고, 달력 날짜/월 선택은 해당 목록 위치로 이동한다.
- 최신순/오래된순과 검색·필터를 유지한다. 달력 모드의 릴리스도 연결선 없는 기사 카드로 표시하며, 일반 리스트 모드의 소프트웨어별 릴리스 이력은 유지한다.
- 동기화 스크롤 엔진을 행사와 공유하고 표시 방식만 구분한다. 날짜 없는 항목은 달력에 배치하지 않고 별도 목록으로 표시한다.

## 개발 업데이트의 최신 소식·제품별 버전 이력

- 기본 탭 `최신 소식`은 기술 글·제안·여러 제품의 릴리스를 실제 발행일순으로 혼합한다. 기존 기술 글 우선/제품별 묶음은 이 보기에서 제거한다. 종류·출처 필터와 달력 표시/숨기기를 제공한다.
- `제품별 버전 이력` 탭은 소프트웨어 하나를 선택해 해당 제품의 릴리스만 표시한다. 버전 번호가 제목이고 발행일·변경 요약·적용일·릴리스 노트 링크를 함께 제공한다. 출시 후보 포함은 기본 켜짐이다.
- 제품 식별은 GitHub 릴리스 URL의 저장소를 우선하고, 없는 경우 수집원 이름을 사용한다. 출처를 식별할 수 없는 릴리스를 임의로 같은 제품으로 묶지 않는다.
- 후보 여부는 기존 버전 문자열의 rc/alpha/beta/preview/dev 표기로 구분한다. Git 부모/분기 관계를 만들지 않는다. 버전 이력의 정렬도 발표일 기준이다.
- 검색·적용한 날짜 범위·정렬은 두 탭이 공유한다. 최신 소식의 종류·출처 조건은 해당 탭에 보존하며 버전 이력에 적용하지 않는다. 제품 선택과 후보 포함 여부는 버전 이력에 보존한다. 필터를 바꿔도 선택 제품은 자동 변경하지 않는다.
- 버전 이력에는 달력을 노출하지 않는다. 최신 소식으로 돌아가면 이전 달력 표시 설정을 유지한다.
