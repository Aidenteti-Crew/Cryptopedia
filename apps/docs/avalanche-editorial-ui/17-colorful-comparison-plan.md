## 2. 관찰과 목표

현재 홈의 소식 배너는 보라/블루/그린/로즈/오렌지 그라데이션을 사용하고, 히트맵은 다양한 색 면을 사용한다. 반면 ‘어떻게 시작할까요’의 두 카드는 배경과 강조색이 모두 동일한 `editorial-surface`와 `editorial-accent`라 두 선택의 구분이 약하다.

하위 화면은 전체 면적에서 어두운 바탕의 비중이 높고, 카드의 미세한 색 차이에 의존한다. B안은 색이 읽히는 면적과 강도를 늘리고, 선택·분류를 빠르게 구별하도록 한다. 가장 중요한 목표는 제목 탐색과 날짜/출처/제품/버전 구분이다.

## 3. 공통 디자인 결정

### 색의 역할

1. **목적지:** 프로젝트 보라, 매크로 블루, 행사 오렌지, 개발 그린. 제목 옆 아이콘, 얇은 상단 강조, 카드 메타 영역에서 반복한다.
2. **콘텐츠 종류:** 실제 데이터의 종류가 여러 개일 때 작은 배지로 구별한다. 릴리스 그린, 기술 아티클 라일락, 출시 후보 앰버. 텍스트 이름을 반드시 함께 표시한다.
3. **조작 상태:** 선택 탭·필터·포커스는 기존 라벤더로 통일한다. 콘텐츠 색과 선택 여부를 혼동시키지 않는다.
4. **상태/중요도:** 취소·연기는 문자와 표시로 전달한다. 공식 근거가 있는 필수 변경·보안 변경만 코랄 강조를 추가한다. 색을 채우기 위해 중요도를 만들지 않는다.

홈의 기존 색을 시작점으로 사용한다.

| 계열 | 기본 색 | 밝은 강조색 | 주 사용처 |
|---|---|---|---|
| 보라 | #7B5EA7 | #C8A9F0 | 프로젝트·사람이 공부하기 |
| 블루 | #3A6EA5 | #A7C8FF | 매크로·협업 |
| 그린 | #2E8B6F | #A5E7D2 | 개발·에이전트에게 전달하기 |
| 오렌지 | #D4854A | #FFD2A1 | 행사 날짜·일정 |
| 로즈 | #C94B6E | #F5B4C5 | 근거 있는 중요한 변경의 소량 강조 |

위 값은 기존 팔레트에 연결한 시작값이다. 밝은 바탕에는 짙은 글자를, 어두운 바탕에는 밝은 글자를 사용한다. 최종 합성 배경과 hover 상태에서 대비를 확인하고 조정한다.

### 카드 구조

모든 항목을 `색이 보이는 메타 영역 + 읽기 편한 본문 영역`으로 통일한다.

```text
┌ 날짜 · 출처/제품              유형 배지 ┐ ← 색을 담는 얕은 영역
│ 제목                                   │ ← 가장 높은 위계
│ 핵심 설명 1–2줄                         │ ← 일정한 어두운 바탕
│ 실제 적용일·장소 등 필요한 추가 정보    │
│ 상세 / 공식 원문                       │
└────────────────────────────────────────┘
```

- 메타 영역의 색 농도를 본문보다 높게 한다. 전체 본문을 선명한 그라데이션으로 채우지 않는다.
- 원칙: 라운드 16px, 얇은 색 테두리, 본문 여백 20px(모바일 16px), 항목 간격 12px.
- 메타 영역은 고정 높이를 강제하지 않는다. 긴 출처나 제품명이 줄바꿈되어도 정보가 잘리지 않아야 한다.
- 목록 제목 17–18px/행간 26–28px, 요약 14px/행간 24px, 메타 12px/행간 18px를 시작값으로 삼는다.
- 날짜 그룹은 카드 바깥에 두고, 개별 공개 시각이나 행사 시간은 카드 안에 둔다. 의미 없는 동일 날짜의 반복은 줄인다.
- hover는 테두리와 면을 조금 밝히며, 위치 이동은 넣지 않는다. 키보드 포커스는 별도 외곽선으로 표시한다.

## 4. 화면별 구성

### 홈 — 어떻게 시작할까요

- 왼쪽 ‘사람이 공부하기’: 보라 그라데이션, 밝은 보라 라벨과 큰 책 아이콘.
- 오른쪽 ‘에이전트에게 전달하기’: 그린/틸 그라데이션, 밝은 민트 라벨과 큰 에이전트 아이콘.
- 기존 홈 배너의 색 계열을 쓰되 색의 밝은 부분은 아이콘 쪽으로 보낸다. 텍스트 쪽은 어두운 색을 유지한다.
- 두 카드의 크기·제목 위치·설명 길이·CTA 위치를 맞춘다. 전체 카드가 기존 목적지로 연결된다.
- 데스크톱 2열, 모바일 1열. 새 설명이나 기능을 추가하지 않는다.

### 체인·프로젝트

- 카드 보기: 상단 보라 메타 영역에 아이콘과 분야 배지, 본문에 프로젝트명·두 줄 설명·공식 링크.
- 리스트 보기: 같은 색/모서리/테두리를 사용하며, 메타와 본문을 가로로 압축한다. 모바일에서는 세로로 접는다.
- 분야별로 카드 전체 색을 무작위 배정하지 않는다. 다양한 색은 실제 분야를 구분하는 배지에만 보조적으로 사용한다.
- 분야가 많으므로 실제 33개 카테고리를 확인해 명시적인 색 매핑을 만들고 미매핑은 중립색을 사용한다. 정렬 순서나 검색 결과 순서가 바뀌어도 색이 바뀌면 안 된다.
- 로고가 없으면 기존 중립 아이콘을 쓴다. 임의의 로고를 만들지 않는다.

### 매크로 소식

- 날짜 그룹 아래 블루 메타 영역을 가진 뉴스 카드를 배치한다.
- 공개 시각·출처·종류를 한 묶음으로 보여주고, 제목과 요약의 읽기 영역을 충분히 확보한다.
- 협업·도입은 블루, 거래·시장 지표는 틸, 기타는 라일락 배지로 구분한다. 실제 존재하는 종류만 사용한다.
- 달력 모드에서도 같은 카드를 사용한다. 색 때문에 출처와 유형 필터를 추가하지 않는다.

### 행사·이벤트

- 날짜별 연결 구조 옆에 오렌지 메타 영역의 행사 카드를 배치한다.
- 시간 → 행사명 → 장소·주최자 → 참가 링크 순서. 날짜/시간은 다른 보조 정보보다 먼저 읽혀야 한다.
- 실제 썸네일이 있으면 보조 영역에 사용하며 색 면과 이미지가 경쟁하지 않도록 크기를 제한한다.
- 달력의 일정 있는 날짜는 점/개수와 색 바탕, 선택 날짜는 명확한 테두리로 구별한다. 오늘 표시와 선택 표시도 구별한다.
- 달력과 목록의 동기화 및 1:1 배치를 유지하고, 작은 화면에서 같은 카드가 자연스럽게 한 열로 표시되도록 한다.

### 개발 업데이트

- 전체 업데이트: 월별 그룹과 그린 메타 영역 카드. 공개일·제품·유형·버전의 위계를 명확히 한다.
- 제품별 이력: `전체 · Coreth · Subnet-EVM` 탭 아래 타임라인과 같은 카드를 사용한다. 정식/출시 후보는 텍스트 배지와 마커 모양으로 구별한다.
- 일반 릴리스는 그린, 기술 아티클은 라일락 배지, 출시 후보는 앰버 배지. 같은 항목의 상단·제목·요약에 유형을 반복하지 않는다.
- 공개일과 네트워크 적용일은 서로 다른 라벨로 제공한다. 공식 근거가 있는 중요한 변경만 코랄 라벨을 추가한다.
- 검색·보기 전환·제품 탭의 현재 압축된 배치를 유지한다. 큰 새 배너를 추가해 콘텐츠를 아래로 밀지 않는다.

## 5. 가독성과 비교 기준

- 일반 텍스트 명암비 4.5:1 이상, 큰 제목 3:1 이상. gradient의 가장 밝은 부분과 hover 상태까지 확인.
- 색을 보지 않아도 날짜/출처/유형/선택 상태가 텍스트와 모양으로 구별되어야 한다.
- 네 화면의 첫 콘텐츠 위치는 A안보다 불필요하게 내려가지 않아야 한다.
- 제목, 실제 데이터가 긴 카드, 원문 링크, 빈 결과, 필터 팝오버, 모바일 줄바꿈을 함께 확인한다.
- A/B는 동일 데이터·검색 조건·정렬·뷰포트에서 비교한다. 네 화면과 홈의 해당 섹션을 같은 크기로 캡처한다.
- 질문: 어떤 버전에서 항목 경계가 더 뚜렷한가? 날짜/출처/버전을 더 빨리 찾는가? 여러 항목을 읽을 때 색이 피곤한가?

## 6. 후속 구현 순서와 비교 제공

1. 공통 색 변수와 카드 구조, 홈의 두 진입 카드 및 매크로 대표 목록을 먼저 구현한다.
2. 실제 PC/모바일 화면으로 색 강도와 글자 대비를 확인한 뒤 네 화면 전체로 확장한다.
3. 검색·필터·달력·제품 탭·원문 링크의 기존 동작을 검증한다.
4. A안 작업 폴더는 기존 :3000, B안은 사용 가능한 별도 포트(우선 :3001)로 실행한다. 이때 공유 API의 CORS에 B안 주소를 로컬 실행 옵션으로 추가한다. DB는 같은 읽기 데이터를 사용한다.
5. 두 URL과 같은 위치의 A/B 캡처를 제공한다. 현재 시점에는 B안 서버와 변경 화면이 아직 없다.

구현 대상: `ecosystem-page.tsx`, `globals.css`의 공통 카드 규칙, 네 화면의 항목 컴포넌트 및 `development-changelog.tsx`/`development-update-row.tsx`. 새 공통 UI가 필요하면 이 브랜치에서만 추가한다.
