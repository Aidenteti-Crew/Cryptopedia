# 개발 업데이트 목록과 상세 연결

- 목표: 가로로 긴 카드를 줄이고 기존 상세 패널의 변경 내용/근거/적용 일정/원문을 탐색 중 함께 읽는다.
- 1280px 이상: 목록 40%, 상세 60%. 아래로 읽기 시작하면 상단 제목/검색/필터가 페이지와 함께 올라가고 읽기 영역이 확장된다. 이후 두 영역은 각각 독립 스크롤한다. 위로 스크롤하면 상단이 복귀하며 양쪽 읽던 위치는 유지된다. 목록은 제목·날짜·유형·제품·버전 위주로 압축한다.
- 최초 최신순의 첫 결과 선택. 수동 선택은 정렬/필터 후에도 결과에 남으면 유지하고, 사라지면 현재 결과의 첫 항목으로 전환. 빈 결과에는 이전 상세를 남기지 않는다.
- 좁은 화면: 목록만 표시. 명시적으로 항목을 누르면 기존 Sheet 상세 열기/닫기/포커스 복귀. 진입/검색 때문에 자동으로 Sheet를 열지 않는다.
- 전체 업데이트/제품별 버전 이력 모두 같은 상세를 사용한다. 제품별 시간선과 공식 원문/비교 링크 기능 유지.
- 관련 아티클-릴리스 연결은 기존 데이터에 명시적인 관계가 없어 생성하지 않는다.
- 검증: 초기 선택·빈 결과 SSR, 실제 항목 전환/필터/제품 탭, 모바일 자동 팝업 없음과 클릭 상세, 원문·적용일 보존, 가로 넘침.

## 구현 결과

- 기존 `DevelopmentUpdateDetail`에 inline 렌더링을 추가해 같은 본문을 데스크톱 패널과 모바일 Sheet에서 재사용한다.
- 목록/버전 카드는 compact 모드와 선택 표시를 지원한다. 근거·적용 일정·원문/비교 링크는 오른쪽 또는 모바일 상세에서 제공한다.
- 데스크톱 1440×1000 기준 목록 약 418px, 상세 약 626px. 초기의 600px 고정 높이는 푸터가 너무 빨리 나타나는 문제로 후속 수정에서 제거했다.
- 실제 검증: 최초 Helicon 표시, 다른 글 선택 시 오른쪽 교체(모달 없음), Helicon 검색 시 1개/상세 교체, 없는 검색 시 0개/이전 상세 제거, Coreth 4개/Subnet-EVM 7개와 대응 상세 확인.
- 수동 선택한 Subnet-EVM 버전은 오래된순 정렬 후에도 유지됨을 확인.
- 390px에서 자동 모달 없음/가로 넘침 없음. 항목 클릭 시 기존 상세가 열리고, 닫으면 원래 버전 버튼으로 포커스 복귀. 브라우저 오류 없음.
- 관련 테스트 26개 통과, ESLint/diff 검사 통과. 전체 타입 검사에는 기존 KaaS 오류 8개만 남아 있다.
- 증빙: `/private/tmp/development-reader-desktop.png`, `/private/tmp/development-reader-versions.png`, `/private/tmp/development-reader-mobile-detail.png`.
- B안 :3001에 반영. A안 :3000 보존. B안 빌드 캐시는 `/private/tmp/ecosystem-colorful-next-before-reading-layout-20261016`에 보관 후 재생성했다.

## 푸터와 본문 높이 보완

- 개발 목록의 고정 높이와 내부 스크롤을 제거하고 자연스럽게 페이지 높이에 반영한다. 오른쪽만 sticky 상세로 유지한다.
- 공통 main 최소 높이를 데스크톱 100dvh, 모바일 100dvh−64px로 맞춰 짧은 결과에서도 푸터가 첫 화면 안으로 올라오지 않게 한다.
- 브라우저 1440×1000: 개발 목록 overflow=visible, 상세 position=sticky, 푸터 top=3585px, main min-height=1000px 확인.
- 증빙: `/private/tmp/development-normal-page-height.png`.

## 상세 하단 가림 보완

상세의 최대 높이가 화면 전체 높이만 참고해 상단 제목/필터 영역 아래에서 패널 하단이 화면 밖으로 나갔다. 이제 실제 패널 top과 화면 하단 24px 여백을 기준으로 남은 높이를 계산한다. 페이지 스크롤/창 크기/목록 크기 변화에 맞춰 갱신하며 렌더 상태를 불필요하게 바꾸지 않는다.

실제 1440×1000에서 상세 top=376.5px, 높이=600px, bottom=976.5px. 오른쪽만 끝까지 스크롤해 공식 기술 블로그 링크가 화면 안에 보이며 page scroll=0 확인. 증빙: `/private/tmp/development-detail-bottom-visible.png`.

## 최종 정정 — 상세 전체를 본문 높이에 반영

사용자 의도는 화면 안에 상세 창을 가두는 것이 아니라 오른쪽 내용 전체만큼 본문이 이어지는 것이었다. 위 동적 최대 높이 계산, sticky 및 내부 overflow를 제거했다. 오른쪽도 자연 높이로 렌더링되며 양쪽 중 더 긴 내용 뒤에 공통 푸터가 배치된다.

브라우저에서 상세 clientHeight=scrollHeight=1057px, maxHeight=none, overflow=visible, position=static 확인. 창 높이 633px를 그대로 유지한 채 페이지 스크롤로 원문 링크까지 읽고 푸터가 상세 뒤에 있음을 확인했다. 관련 테스트 3개 통과. 증빙: `/private/tmp/development-detail-natural-height.png`.

## 현재 확정 — 양쪽 독립 스크롤

앞선 해석을 정정했다. 양쪽 표시 높이를 동일한 작업 영역에 맞추고 각각 overflow-y-auto/overscroll-contain을 사용한다. 공통 본문의 최소 높이는 유지한다. 목록 필터 변경 시 왼쪽은 맨 위로, 항목 선택 시 오른쪽은 맨 위로 복원한다.

실제 창 높이 633px 그대로 검증: 오른쪽 끝 스크롤 826px/원문 링크 보임, 왼쪽 0px/페이지 0px 유지. 이어서 왼쪽만 500px 스크롤 → 오른쪽 826px/페이지 0px 유지. 오른쪽과 왼쪽의 콘텐츠가 각각 독립적으로 끝까지 보임을 확인했다. 증빙: `/private/tmp/development-independent-scroll.png`.

## 상단 스크롤과 읽기 영역 연동

독립 스크롤로 인해 상단 영역이 그대로 남던 동작을 보완했다. 데스크톱 읽기 영역의 세로 휠/방향키/PageUp·Down 입력에서 상단이 보이면 먼저 페이지를 이동시킨다. 작업 영역이 화면 상단 24px에 도달하면 각 영역의 기본 스크롤로 이어지고, 위 방향 입력은 상단 필터를 다시 드러낸다. 입력/버튼의 키 조작, 가로 휠, 확대/브라우저 단축키는 가로채지 않는다. 모바일의 기존 페이지/Sheet 흐름은 유지한다.

브라우저 휠 이벤트와 영역 스크롤로 검증: 창 높이 633px 유지, 상단 이동 후 page=352px/영역 top=24.5px/읽기 높이=583px/오른쪽=180px/왼쪽=0px. 위 방향 입력 후 page=0px/필터 top=268.5px/읽기 높이=231px로 복귀하면서 오른쪽=180px/왼쪽=0px 유지. 증빙: `/private/tmp/development-toolbar-hidden.png`, `/private/tmp/development-toolbar-returned.png`.

## 높이 고정 보완 — 현재 동작

스크롤 중 패널 높이/스크롤바 크기가 달라지는 문제를 해결하기 위해 위치 기반 높이 계산, ResizeObserver 및 높이 갱신용 scroll/resize 리스너를 제거했다. 데스크톱 양쪽 영역은 처음부터 `100dvh - 48px` 높이를 사용하고, 상단 이동/복귀 중에는 위치만 바뀐다. 독립 스크롤과 읽던 위치는 유지한다.

브라우저 창 633px에서 초기/상단 숨김/상단 복귀 모두 상세 높이 583px, 콘텐츠 높이 1057px로 동일. 오른쪽 180px/왼쪽 0px 위치도 유지됨을 확인했다. ESLint와 diff 검사 통과.
