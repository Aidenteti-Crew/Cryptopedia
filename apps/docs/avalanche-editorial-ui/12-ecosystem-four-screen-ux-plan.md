# 생태계 하위 네 화면 UI/UX 통합 기획

기준: 2026-10-15 / feature/ecosystem-readability. 승인 후 2026-10-16 구현을 완료했다. 실행 내역과 검증 결과는 13-four-screen-implementation-result.md를 참조한다. 아래 내용은 승인된 기획 기준이다. 생태계 홈은 디자인 기준이며 개편 대상에 포함하지 않는다.

## 1. 선택한 레퍼런스와 적용 범위

| 화면 | 주 레퍼런스 | 참고할 동작과 구조 | Proof of Cherry 적용 |
|---|---|---|---|
| 체인·프로젝트 | [Alchemy Dapp Store](https://www.alchemy.com/dapps) | 검색, 분야·체인 선택, 프로젝트 설명과 분류 | 분야 체크박스, 카드/리스트, 설명·공식 링크 |
| 매크로 소식 | [The Block News](https://www.theblock.co/news) | 주제별 탐색, 날짜/시간과 제목 중심의 최신 뉴스 | 실제 수집 유형, 공개일·출처를 먼저 보여주는 간결한 피드 |
| 행사·이벤트 | [Luma Seoul](https://luma.com/seoul) | 행사명·주최자·장소·이미지의 위계 | 날짜별 타임라인, 시간·장소·신청 행동의 우선순위 |
| 개발 업데이트 | [GitHub Changelog](https://github.blog/changelog/) | 유형 탐색 바, 필터, 월별 그룹과 제목·태그 | 실제 콘텐츠 유형과 체크박스, 월별 목록, 제품별 버전 이력 |

[DefiLlama Protocols](https://defillama.com/protocols)도 비교했다. 이름·카테고리 열을 통한 비교는 참고할 수 있으나, 현재 디렉터리는 TVL/매출/시가총액 데이터가 없어 금융 지표 중심 표를 주 구조로 채택하지 않는다. 위 선정은 현재 서비스 목적과 데이터에 맞춘 설계 판단이다.

레퍼런스의 정보 배치와 조작을 참고한다. 서비스별 로고·브랜드 색상·마케팅 영역을 가져오지 않는다. 확인한 공개 페이지의 구조를 기준으로 하며 모든 화면의 픽셀 단위 시각 비교를 완료했다는 뜻은 아니다.

홈의 큰 히어로 캐러셀은 홈의 역할에 맞게 유지한다. 하위 화면은 공통 제목·짧은 설명·탐색 바로 바로 진입한다. 반복 뉴스 행은 배경 박스보다 구분선과 간격을 사용하고, 탐색용 프로젝트/행사에는 홈과 같은 둥근 카드를 사용한다.

## 3. 네 화면의 공통 탐색 규칙

```text
[화면 아이콘] 화면 제목 · 전체 건수
              한 줄 설명

[검색................................................]
[주요 유형/보기]                          [필터 N]

필터를 열면: 각 분류의 체크박스가 한 번에 보이는 패널
검색 결과 N개             [초기화] [정렬] [보기 아이콘]
콘텐츠
```

- 검색은 화면별 목적을 명시한다. 변경 시 결과 수를 알리고 목록을 갱신한다.
- 복수 선택은 체크박스. 같은 그룹 안은 OR, 그룹 사이는 AND다. 예: Coreth 또는 Subnet-EVM 중 Mainnet 항목.
- 선택하지 않은 그룹은 전체. 아무 선택도 없는 상태를 결과 0건으로 해석하지 않는다.
- 상세 옵션별 드롭다운을 연속으로 열게 하지 않는다. 필터 버튼 한 번으로 제품/분야/환경 등의 옵션을 직접 선택한다.
- 정렬·제품별 버전 보기의 기준 제품처럼 하나만 고르는 제어는 단일 선택을 유지한다.
- 날짜는 시작일/종료일을 정한 뒤 적용한다. 첫 날짜 클릭만으로 결과를 바꾸지 않는다.
- 단일 선택 값을 칩으로 중복 표시하지 않는다. 복수 선택 요약은 필요할 때 패널이 닫힌 상태에만 표시한다.
- 분류가 1개뿐이면 필터를 숨기고 항목의 보조 정보로 표시한다. 출처가 X 하나면 출처 필터를 두지 않는다.
- 필터 초기화의 범위를 일관되게 한다. 상세 조건 초기화는 검색어/주요 유형을 유지하고, 전체 초기화는 모든 탐색 조건을 초기화한다.
- 프로젝트 분야 선택은 기존 바깥 클릭/Escape 닫기를 유지한다. 공통 필터를 팝오버/패널로 추출할 때 이 동작을 회귀 기준으로 삼는다.
- 모바일에는 긴 옵션 목록을 세로로 배치한다. 옵션이 많으면 필터 패널 내부를 스크롤하고 하단 결과 수/닫기 접근을 보장한다.
- 화면 이동 후 돌아왔을 때 검색·필터·보기·목록 위치를 복원하도록 후속 상태 보존을 설계한다. 영구 저장과 URL 공유는 현재 상태 기반 라우팅과 별도 검토한다.

## 4. 체인·프로젝트 — 분야 중심 디렉터리

목표: 어떤 프로젝트인지 판단하고 공식 페이지/문서에 빠르게 도달한다.

```text
체인·프로젝트 · N개
[프로젝트명·설명·개발사 검색.........................]
[분야 필터 N]                         [이름순] [카드][리스트]

필터 펼침
[분야 검색........]
☐ Analytics & Data   ☐ DeFi      ☐ Infrastructure
☐ Gaming             ☐ Wallets  ☐ ... 실제 분야

[아이콘  이름]        [아이콘  이름]        [아이콘  이름]
분야                   분야                  분야
설명 2줄               설명 2줄              설명 2줄
개발사                  개발사                개발사
공식 홈페이지 · 문서
```

- 기본 카드: 데스크톱 3열, 태블릿 2열, 모바일 1열. 여러 분야를 선택하면 하나의 결과 그리드로 모은다.
- 목록은 24개씩 더 보기로 탐색 부담을 줄인다. 필터·검색은 화면에 표시된 24개만이 아니라 전체 수집 범위를 대상으로 해야 하며, 현재 500건 API 상한을 넘는 경우 서버 페이지 처리가 필요하다.
- 모든 분야를 세로로 길게 펼쳐 같은 프로젝트 탐색을 반복하기보다, 검색 결과와 분야 선택을 중심으로 정리한다.
- 리스트: 이름/분야/짧은 설명/개발사/공식 링크 순. 금융 지표가 없는 상황에서 빈 숫자 열을 만들지 않는다.
- 실제 공식 로고가 제공될 때만 사용하고, 없으면 현재의 중립 아이콘으로 표시한다.
- 홈페이지와 문서는 각각 분명한 링크로 제공한다. 전체 카드 클릭과 내부 링크가 서로 충돌하지 않도록 링크를 중첩하지 않는다.
- 정렬 기본은 이름순. 기존 중요도순은 기준과 데이터 의미를 설명할 수 있을 때 보조로 제공한다.
- 분야가 많아도 한 번의 필터 열기로 선택할 수 있도록 분야 검색과 선택 요약을 함께 제공한다.

## 5. 매크로 소식 — 날짜·출처가 보이는 뉴스 피드

목표: 어떤 소식이 언제, 어디에서 나왔는지 빠르게 읽는다.

```text
매크로 소식
[제목·내용·출처 검색.................................]
[전체] [협업·도입] [거래·시장 지표] [...]       [필터]
검색 결과 N개                              [최신순] [달력]

날짜 그룹
공개일/시간 · 출처 · 유형
제목
요약 최대 2줄                                      원문 ↗
─────────────────────────────────────────────────────
```

- The Block의 시각/주제 위계를 참고하되, 분류는 현재 COLLAB/VOLUME/OTHER를 명확하게 번역한다. Regulation/Macro 등의 새 주제를 데이터 없이 만들지 않는다.
- 출처 이름과 공개일은 기본 노출. 긴 설명은 요약과 상세로 분리한다. 출처가 하나면 필터를 숨겨 조작을 줄인다.
- 날짜 표시 기준은 KST. 원문이 시각을 제공하지 않으면 날짜만 표시한다. 수집 시각을 공개 시각으로 대체하지 않는다.
- 기본은 목록, 달력은 아이콘으로 열고 닫는다. 달력 열림에서는 좌우 1:1, 목록 스크롤과 날짜 선택 연동을 유지한다.
- 같은 원문 URL의 중복은 합치되, 같은 주제를 다룬 서로 다른 출처를 임의로 한 기사로 합치지 않는다.
- 현재 매크로 API의 100건 한도 때문에 전체 검색을 보장하려면 페이지 처리가 선행되어야 한다.

## 6. 행사·이벤트 — 일정과 참여 행동 중심

목표: 날짜를 고르고 시간·장소·주최자를 확인한 뒤 상세나 신청으로 이동한다.

```text
행사 및 이벤트
[행사명·주최자·장소 검색.............................]
검색 결과 N개                    [필터] [날짜순] [달력]

┌───────────────── 50% ────────────┬──────────── 50% ────┐
│ 월 이동 / 오늘                    │ 날짜 · 요일         │
│ 날짜 숫자                         │ 시간 · 진행 상태    │
│ 건수 · 제목 2줄 · +N              │ 행사명              │
│                                   │ 주최자 · 장소/온라인│
│                                   │ 상세 / 참가 신청    │
└───────────────────────────────────┴────────────────────┘
```

- Luma의 행사 정보 위계를 활용한다. 실제 imageUrl이 있으면 작은 썸네일을 선택적으로 사용한다. 이미지가 없어도 같은 읽기 순서를 유지한다.
- 시간 → 행사명 → 주최자·장소 → 행동 순. 신청 링크가 실제로 존재하면 참가 신청을 우선 행동으로 제공한다.
- 매진/잔여석/참가자 수는 현재 API에 없는 값이므로 표시하지 않는다. 기존 UPCOMING/ONGOING/PAST/CANCELLED/POSTPONED 상태만 사용한다.
- 예정/지난 탭과 별도 지난 전체보기는 다시 만들지 않는다. 하나의 연속 일정 안에서 과거/미래를 탐색한다.
- 달력과 목록 너비·시작 위치·높이를 맞춘다. 넓은 화면에서는 1:1, 작은 화면에서는 위아래로 배치한다.
- 첫 진입은 실제 일정으로 이동한다. 빈 날짜를 직접 선택하면 한 줄 안내와 가까운 날짜 이동 버튼을 제공한다.
- 스크롤이 멈춘 뒤 월을 갱신해 번쩍임을 억제한다. 숨긴 달력을 다시 열 때 보고 있던 날짜로 연결한다.
- 취소/연기는 색상만으로 구분하지 않고 글자로 표시한다. 행사 시간대와 KST의 관계를 분명히 한다.

## 7. 개발 업데이트 — 변경 기록과 버전 흐름

목표: 변경 성격과 제품, 공개 시점, 실제 네트워크 적용 시점을 구분한다.

```text
개발 업데이트
[전체 업데이트] [제품별 버전 이력]
[제목·내용·버전·출처 검색............................]
[전체] [릴리스] [기술 아티클] [ACP 제안]       [필터 N]

필터 펼침
제품             환경              변경 성격
☐ AvalancheGo    ☐ Mainnet         ☐ 필수 업데이트
☐ Coreth         ☐ Fuji Testnet    ☐ 호환성 변경
☐ Subnet-EVM     ☐ 기타/미확인     ☐ 보안 수정
릴리스 선택 시 정식/프리릴리스/미확인 체크박스
공개일 범위

연도·월
날짜 · 유형       제목
                  제품 · 버전 · 중요한 변경 · 공식 링크
```

- 전체 보기는 월별 그룹, 간결한 구분선, 제목 중심의 GitHub Changelog 구조를 유지한다. 긴 본문은 상세 패널에서 읽는다.
- 제품 태그를 누르면 제품 조건으로 바로 좁힌다. 체크박스는 복수 선택을 지원하며 어느 조건이 적용됐는지 필터 개수와 선택 상태로 확인한다.
- 제품별 버전 이력은 한 제품의 공개 순서를 선과 점으로 연결한다. 정식/출시 후보/미확인을 글자와 점 모양으로 구분하며 Git 부모/분기 관계를 추정하지 않는다.
- 기술 아티클과 릴리스는 유형, 필수/보안/호환성은 변경 성격으로 분리한다. 데이터에 없는 Improvements/Retired를 만들지 않는다.
- 달력은 제공하지 않고 공개일 범위 검색을 유지한다. 적용 일정은 공식 근거가 확인된 것만 KST/UTC와 함께 상세에 표시한다.
- 공식 출처와 제공된 버전 비교 링크를 보존한다. 중요 공지는 근거가 있고 시의성이 있는 항목만 표시하며, 없으면 섹션을 숨긴다.

## 8. 상태·접근성·데이터 검증

- 로딩: 홈 색상으로 최소한의 스켈레톤, 제목/필터 레이아웃 높이는 유지한다.
- 빈 검색: 검색 조건에 맞는 자료 없음 + 조건 초기화. 데이터 자체 없음과 구분한다.
- 빈 날짜: 직접 선택했을 때만 안내 + 가까운 날짜 이동. 기본 화면에 빈 오늘 구획을 만들지 않는다.
- 오류: 읽기 실패와 다시 시도. 데이터가 0개라고 오인하게 하지 않는다.
- 체크박스는 fieldset/legend와 연결된 label, Space/Tab 조작을 지원한다. 팝오버 Escape/바깥 클릭, 상세 패널 초점 복원을 검증한다.
- 모든 필터는 현재 데이터에서 제공되는 필드만 사용한다. 미확인과 해당 없음은 구분한다.
- AvalancheGo 누락/날짜 충돌은 기존 조사 기록대로 수집 보완이 필요하다. 이번 기획의 완성도와 데이터 완전성을 동일시하지 않는다.

## 9. 구현 순서와 완료 기준

1. 체크박스 필터 즉시 개선: 이번 요청에서 구현. 복수 선택/초기화/제품 태그/버전 보기 상태를 검증한다.
2. 공통 탐색 요소 정리: 공통 헤더, 검색, 필터 패널, 결과 수/정렬/아이콘 위치와 홈 색상 토큰을 통일한다.
3. 프로젝트 디렉터리: 분야 탐색 및 카드/리스트, 공식 링크 우선순위를 반영한다.
4. 매크로·행사: 뉴스와 일정에 맞는 메타데이터, 보기 전환과 스크롤 복원을 반영한다.
5. 개발 업데이트 마감: 월별 목록/필터/상세/버전 흐름을 공통 규칙으로 점검한다.

수용 기준: 세 번 이상의 드롭다운 열기 없이 복수 조건 선택, 검색/선택 유지, 1440/834/390px에서 가로 넘침 없음, 읽기 순서와 출처 명확, 일정/공개일 혼동 없음, 홈에서 넘어왔을 때 색상·글꼴·내비게이션·여백의 연속성 유지. 각 단계는 실제 데이터와 브라우저로 확인한다.
